Exercise 11: Web Application Reconnaissance with Firefox Developer Tools

Objective

Observe HTTP requests and responses generated by OWASP Juice Shop using Firefox Developer Tools on Kali Linux.

Lab Environment

* Host machine: MacBook
* Virtualization: VirtualBox
* Testing machine: Kali Linux
* Target machine: Ubuntu Linux
* Target application: OWASP Juice Shop
* Target address: http://192.168.56.2:3000/

Procedure

1. Opened OWASP Juice Shop in Firefox on Kali Linux.
2. Opened Developer Tools and selected the Network tab.
3. Confirmed that network recording was active.
4. Refreshed the application and observed multiple HTTP GET requests.
5. Selected a request with the path / and inspected its headers.
6. Examined the response headers and explored the Request, Response, and Cache-related details available in Firefox.

Observations

* Multiple HTTP requests appeared when the application loaded.
* The selected request used the GET method.
* The selected request returned HTTP status 304 Not Modified.
* The response headers included caching-related information, including Cache-Control and ETag.
* The response included Connection: keep-alive.
* Firefox displayed no payload for the selected request.
* Firefox did not make response data available for that particular request.

Analysis

The GET method is commonly used by browsers to retrieve web resources.

The 304 Not Modified status indicates that the cached representation can be reused following a conditional request. It is not, by itself, evidence of a failed request.

The Cache-Control and ETag headers provide information used in caching and resource validation. The Connection: keep-alive header indicates that the connection may be kept open for further communication.

The absence of a request payload is normal for many GET requests. The unavailable response data is consistent with the possibility that the selected request was handled through cache validation.

Security Considerations

* Testing was limited to the intentionally vulnerable OWASP Juice Shop instance in my home lab.
* No exploitation or modification of requests was performed.
* The application remains restricted to the isolated lab network.
* The application is accessed over HTTP, so traffic is not encrypted. This is acceptable for this isolated training exercise but is not appropriate for transmitting sensitive information over an untrusted network.

Conclusion

Successfully used Firefox Developer Tools to observe HTTP traffic and inspect request and response metadata for OWASP Juice Shop. Identified a GET request returning 304 Not Modified and examined caching-related response headers.

This exercise established a foundation for further web application security testing.
